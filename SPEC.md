# EdgeDock — спецификация проекта

Личный виджет для Windows 11: тонкая полоска у края экрана, которая при наведении разворачивается в панель. Делается для одного пользователя, для удобства в ежедневной работе. Не продукт: никаких отдельных установщиков, телеметрии, автообновлений и поддержки чужих конфигураций. (Встроенное в exe окно установки добавлено по просьбе пользователя — см. «Упаковка».)

Название `EdgeDock` рабочее, используется в путях и пространствах имён.

## Приоритеты (в этом порядке)

1. Лёгкость для системы. Виджет работает постоянно и не должен быть заметен по нагрузке.
2. Эстетика. Выглядит как родная часть Windows 11, а не как стороннее приложение.
3. Функции. Лучше меньше, но работающих безупречно.

Если функция конфликтует с пунктами 1 или 2 — упрощай функцию, а не жертвуй лёгкостью или внешним видом. При сомнениях спроси, а не выбирай молча.

## Стек

* C#, .NET 10, WPF. `TargetFramework`: `net10.0-windows10.0.19041.0` (нужен для WinRT API).
* UI-компоненты: библиотека WPF UI (lepoco/wpfui). Её тему и акцент переключает наш ThemeService (не `ApplicationThemeManager`: тот перекрашивает фон главного окна, а это прозрачная полоска). Значки — только Segoe Fluent Icons через глифы из токенов, не `SymbolIcon` WPF UI (у него свой шрифт).
* Аудиоустройства: NAudio.Wasapi 3.1 (CoreAudio) для перечисления и уведомлений + собственный интероп `IPolicyConfig` для смены устройства по умолчанию.
* Outlook 2013: COM через позднее связывание (`dynamic`), без зависимости от Office PIA.
* Музыка из Яндекс Браузера: собственное расширение браузера (Manifest V3, без сторонних библиотек) + WebSocket-сервер на 127.0.0.1 в виджете (`TcpListener` + `WebSocket.CreateFromStream`, без ASP.NET).
* Упаковка: один EdgeDock.exe со всем .NET внутри (self-contained single-file, без сжатия — сжатые библиотеки распаковывались бы в память; собственная память та же, ~25–40 МБ). Без MSIX и отдельного установщика: exe, запущенный не из папки установки (её записывает `%LocalAppData%\EdgeDock\install.json`), показывает окно установки — папка, галочки «автозапуск» и «ярлык в Пуске», «Установить и запустить»; затем помощник для расширения Яндекс Браузера (открывает `browser://extensions`, копирует путь). Обновление — тем же окном: запущенный виджет закрывается по именованному событию `Local\EdgeDock.Exit`. Сборки из `bin\` окно установки не показывают. Релизы собирает GitHub Actions по тегу `v*`.
* Новые зависимости не добавлять без явной причины.

## Правила производительности (обязательные)

Бюджет: ~0% CPU в простое, память до ~100 МБ.

* События вместо опроса. `FileSystemWatcher` для скриншотов, события медиа-сессии для музыки, `IMMNotificationClient` для аудиоустройств. Опрос допускается только для календаря (раз в 5 мин).
* Свёрнутое состояние = сон. Анимации остановлены, превью выгружены, скрытые модули не отрисовываются. Модули создаются лениво при первом разворачивании.
* Превью. Декодировать сразу в размер миниатюры (`DecodePixelWidth` ≈ 200), кэшировать на диске в `%LocalAppData%\EdgeDock\cache`. Полноразмерные изображения в памяти не держать.
* Запрещено: `BlurEffect`, `DropShadowEffect` и любые `Effect` WPF (программный рендеринг, дорого). Размытие фона — только системное через DWM.
* Анимации только через `Opacity` и `RenderTransform`, не через `Width`/`Height`/`Margin`.
* Полноэкранные приложения. Если на мониторе виджета активно полноэкранное приложение (`SHQueryUserNotificationState` + проверка монитора), виджет скрывается и полностью замирает, включая таймеры опроса. Игры в эксклюзивном полноэкранном режиме и режим презентации скрывают виджет всегда. Полноэкранное окно на другом мониторе виджет не скрывает.
* COM-объекты Outlook освобождать сразу после использования (`Marshal.ReleaseComObject`), иначе процесс Outlook не закроется после выхода пользователя.

## Дизайн

* Фон: системный акрил/Mica через DWM, скруглённые углы (`DWMWA_WINDOW_CORNER_PREFERENCE`), тонкая полупрозрачная светлая обводка. Если системный акрил невозможен без активации окна — фон без размытия (полупрозрачный цвет темы): не забирать фокус важнее.
* Тема: автоматически следует светлой/тёмной теме Windows и системному цвету акцента, реагирует на их смену на лету.
* Шрифты и иконки: Segoe UI Variable, Segoe Fluent Icons. Никаких других наборов иконок.
* Дизайн-токены — только в `Themes/Tokens.xaml`. Весь интерфейс берёт цвета, отступы, радиусы и длительности оттуда, никаких захардкоженных значений в разметке.
  * отступы: сетка 8 px (4 / 8 / 16 / 24);
  * радиус: 8 px для карточек и кнопок, 4 px для мелких элементов;
  * разворот: 200 мс, ease-out; сворачивание: 150 мс; без «пружинных» эффектов.
* Цвет: акцент — только для активных состояний и напоминания о встрече. Остальное — нейтральные цвета темы.
* У всех интерактивных элементов есть состояния наведения и нажатия.
* Свёрнутая полоска почти незаметна. Оживает только когда скоро встреча: один мягкий переход в цвет акцента, без пульсации.
* На экране нет никаких технических счётчиков (CPU, память, FPS) — ни в релизе, ни в отладке.

## Поведение дока

* Окно без рамки, `Topmost`, прозрачный фон. Стили `WS_EX_TOOLWINDOW` (не видно в Alt+Tab и панели задач) и `WS_EX_NOACTIVATE` (не забирает фокус).
* Свободное положение. Виджет можно перетащить в любое место экрана. Два вида свёрнутого состояния:
  * у края (левый, правый или верхний) — тонкая полоска;
  * в свободном месте — компактная «таблетка» (скруглённый прямоугольник ~40×120 px или кружок, выбрать на этапе 1 и показать пользователю).
* Магнит. Если при перетаскивании виджет оказался ближе ~24 px к краю рабочей области, он прилипает к краю и превращается в полоску. Если отпустить дальше — остаётся свободной таблеткой. Во время перетаскивания показывать лёгкую подсказку, что сейчас произойдёт прилипание.
* Только внешние края. Прилипание работает только к краям, в которые упирается курсор. Край монитора, к которому примыкает другой монитор (стык), не считается краем: курсор проходит через него насквозь, и полоска там срабатывала бы случайно.
* Как перетаскивать. В свёрнутом виде — зажать и тянуть саму полоску/таблетку. В развёрнутом — за ручку-заголовок панели. Нажатие кнопки мыши отменяет таймер разворота; перетаскивание начинается после сдвига на 4+ px (иначе это клик).
* Закрепление. Пункт «Закрепить положение» в трее: когда включено, перетаскивание отключено, чтобы случайно не сдвинуть виджет.
* Направление разворота. Панель раскрывается в сторону, где больше места, и никогда не выходит за рабочую область экрана (не залезает под панель задач). У края — раскрывается от края внутрь экрана.
* Сохранение позиции. Запоминать монитор и позицию в долях рабочей области (0…1), а не в пикселях, чтобы положение переживало смену разрешения и масштаба. Если сохранённый монитор отключён — перенести виджет на основной монитор в то же относительное место.
* Положение по умолчанию — верхний край основного монитора, по центру.
* Верхний край разрешён, но там особенно важна задержка активации (вкладки браузера и заголовки окон).
* Активация (главное место, где легко испортить удобство):
  * зона активации — только сама полоска, не весь край экрана;
  * разворот после задержки 300 мс непрерывного наведения (случайное касание не срабатывает);
  * сворачивание через 500 мс после ухода мыши;
  * во время перетаскивания файла (`DragEnter`) полоска разворачивается сразу, без задержки.
* Иконка в трее, меню: «Закрепить положение» (галочка), «Вернуть на место» (к положению по умолчанию, на случай, если виджет потерялся), «Открыть настройки» (открывает JSON-файл в редакторе по умолчанию), «Открыть папку логов», «Перезагрузить настройки», «Выход».
* Автозапуск: опция в настройках, реализуется ярлыком в `shell:startup`.

## Архитектура

```
EdgeDock/
  App.xaml, App.xaml.cs
  DockWindow.xaml(.cs)        — окно, перетаскивание, прилипание, разворот/сворачивание
  Themes/Tokens.xaml          — дизайн-токены
  Core/
    IDockModule.cs            — общий интерфейс модулей
    PlacementService.cs       — позиция, магнит к краям, направление разворота, мониторы
    SettingsService.cs        — settings.json (правит пользователь) + state.json (пишет виджет)
    FullscreenWatcher.cs
    Log.cs                    — тихий лог
  Modules/
    Pocket/        (полка + скриншоты)
    Meeting/
    Media/
    Audio/
    Pins/
```

`IDockModule`: `Id`, `CreateView()` (ленивое создание), `OnExpanded()`, `OnCollapsed()` (освободить ресурсы), `Suspend()` / `Resume()` (полноэкранный режим), флаг `HasAttention` (для индикации на свёрнутой полоске). Модули не знают друг о друге, кроме явно описанных связей (режим созвона).

## Настройки

Два файла в `%LocalAppData%\EdgeDock\`:

* `settings.json` — правится руками, виджет в него не пишет. Окна настроек в первой версии нет. Перечитывается по пункту меню в трее. При ошибке в JSON — оставить прежние настройки и записать ошибку в лог.
* `state.json` — пишет только виджет: позиция, закрепление, содержимое полки. Руками править не нужно.

`settings.json`:

```json
{
  "dock": { "snapDistancePx": 24, "width": 360,
            "expandDelayMs": 300, "collapseDelayMs": 500, "autostart": true },
  "modules": ["meeting", "pocket", "media", "audio", "pins"],
  "pocket": { "screenshotsFolder": null, "shelfRemoveAfterDrag": false },
  "meeting": { "lookaheadHours": 8, "attentionMinutes": 10 },
  "audio": {
    "favoriteOutputs": ["Speakers (Realtek)", "Headset (Jabra)"],
    "favoriteInputs": ["Microphone (Realtek)", "Headset Microphone (Jabra)"],
    "callMode": { "output": "Headset (Jabra)", "input": "Headset Microphone (Jabra)" }
  },
  "pins": [
    { "type": "phone", "label": "Офис", "value": "+7 000 000-00-00" },
    { "type": "link",  "label": "Портал", "value": "https://example.com" },
    { "type": "tag",   "label": "Проект", "value": "#project-x" }
  ]
}
```

`state.json`:

```json
{
  "dock": { "mode": "edge", "edge": "top", "monitor": "\\\\.\\DISPLAY1", "x": 0.5, "y": 0.0, "locked": false }
}
```

* `dock.mode`: `edge` (полоска у края `edge`) или `free` (таблетка в точке `x`, `y` — доли рабочей области, центр виджета).
* `dock.monitor` — имя устройства монитора, а не номер: номера меняются при переподключении.
* `screenshotsFolder: null` — системная папка «Снимки экрана» (KnownFolder Screenshots).
* Порядок в `modules` — порядок блоков в панели. Отсутствующий модуль не загружается вообще.

## Модули

### Карман (Pocket): полка + скриншоты

Одна зона, общий принцип: всё перетаскивается внутрь и наружу одинаково.

**Скриншоты**

* Лента из 3–4 видимых превью (край следующего подсказывает, что есть ещё), горизонтальная прокрутка только колесом мыши, новые слева. Стрелок нет: клавиши не работают, так как окно не получает фокус.
* Новые файлы подхватываются через `FileSystemWatcher` (с защитой от чтения недописанного файла: повторить попытку с задержкой).
* Клик — открыть снимок в приложении по умолчанию. Кнопка «В папке» — `explorer.exe /select,"<путь>"`.
* Перетаскивание превью наружу — как файл.

**Полка**

* Приём: файлы из Проводника, изображения и файлы из браузера. Если у данных нет пути на диске, сохранить их в `%LocalAppData%\EdgeDock\shelf`.
* Для обычных файлов хранится ссылка. Если исходник исчез — элемент показывается приглушённым с пометкой, по клику убирается.
* Отдача: `DataObject.SetFileDropList`, `DragDropEffects.Copy`. Множественное выделение, перетаскивание нескольких элементов разом.
* Выделение как в Проводнике: клик — один элемент, Ctrl+клик — добавить/убрать, Shift+клик — диапазон. Двойной клик — открыть файл. Тянут невыделенный элемент — тянется он один.
* Содержимое полки переживает перезапуск. Удаление элемента — вручную (крестик при наведении) или автоматически после перетаскивания, если `shelfRemoveAfterDrag: true`.
* Наши копии в `shelf` удаляются не сразу, а при следующем запуске: получатель (например, Telegram) может читать файл уже после того, как его бросили.
* Известное ограничение: перетаскивание в окна, запущенные от администратора, Windows блокирует — не пытаться обойти.

### Ближайшая встреча (Outlook 2013, COM)

* Подключаться только к уже запущенному Outlook. Если Outlook не запущен — не запускать его, показать спокойное «Outlook не запущен».
* В .NET нет `Marshal.GetActiveObject` — использовать P/Invoke `oleaut32!GetActiveObject` + `CLSIDFromProgID("Outlook.Application")`.
* Календарь: `GetDefaultFolder(9)` (olFolderCalendar). Порядок важен: `Items.Sort("[Start]")`, затем `Items.IncludeRecurrences = true`, затем `Restrict` по диапазону «сейчас … +lookaheadHours». Для фильтра по дате использовать DASL-запрос в UTC, а не строковый формат даты (он зависит от локали).
* Опрос раз в 5 минут, обратный отсчёт считается локально. Все обращения к Outlook — в фоновом потоке (чтение `Body` может заблокировать вызов на время окна безопасности).
* Показывать: название, время, «через N мин» / «идёт сейчас», кнопку «Подключиться».
* Ссылка на подключение: сначала искать в `Location`, затем в `Body` (Teams, Zoom, Meet — регуляркой). Чтение `Body` может вызвать окно безопасности Outlook. Если оно появилось или доступ запрещён — не читать `Body` дальше, а показывать кнопку «Открыть приглашение» (`item.Display()`).
* За `attentionMinutes` до начала: `HasAttention = true`, полоска мягко меняет цвет.
* Рядом с «Подключиться» — кнопка «Режим созвона» (вызывает модуль Audio).

### Музыка

* `GlobalSystemMediaTransportControlsSessionManager`: название, исполнитель, обложка (маленькая), кнопки назад / пауза / вперёд.
* Обновление по событиям `CurrentSessionChanged`, `MediaPropertiesChanged`, `PlaybackInfoChanged`.
* Под треком — полоска времени: сколько прошло, ползунок перемотки, сколько осталось. Источники сообщают позицию только при перемотке, паузе и смене трека (Windows — `TimelinePropertiesChanged`, расширение — по событиям страницы и при скачке позиции); между этим виджет досчитывает её сам раз в секунду, и только пока панель развёрнута и трек играет. Перемотка — `TryChangePlaybackPositionAsync` для Windows (если плеер разрешает). В Яндекс Музыке позицию, длину и перемотку расширение берёт у самого плеера — из того, что он сообщает браузеру (`mediaSession.setPositionState` и обработчик `seekto`, их подслушивает `page.js` в мире страницы); подписи панелей плеера для этого не нужны — они у разных панелей разные («1:23» или «1:23 / 3:45»). Пока плеер о себе не сообщил, время берётся с ползунка «Управление таймкодом» (`max` — длина в секундах). Плеер не сообщает длину — строки нет.
* Лайк (сердечко) — только для Яндекс Музыки: в медиа-сессии Windows оценок нет. Расширение читает состояние кнопки «Нравится» (`aria-pressed`) и нажимает её — лайк сохраняется в аккаунте Яндекс Музыки.
* Под временем — полоска общей громкости Windows на текущем устройстве вывода: значок включает и выключает звук, колесо мыши меняет громкость по 2%. Изменения извне приходят событием; к устройству полоска подключается только пока панель развёрнута.
* Нет активной сессии — блок скрывается целиком (вместе с полоской громкости).
* Обложка декодируется сразу в маленький размер (96 px) и только пока панель развёрнута.
* Яндекс Браузер не сообщает Windows о воспроизведении (даже с флагом `hardware-media-key-handling`), поэтому для него есть второй источник — наше расширение `BrowserExtension/` (установка: `BrowserExtension/README.md`). Оно читает Media Session вкладки Яндекс Музыки и передаёт трек виджету по WebSocket на `127.0.0.1:48620`; виджет пускает только это расширение (проверка ID в заголовке Origin). Кнопки из виджета расширение нажимает на странице.
* Расширение не требует ручных действий после установки: при каждом запуске оно встраивается во вкладки Яндекс Музыки, открытые раньше (без F5), а при подключении называет виджету свою версию — если в виджете (внутри exe) расширение новее, виджет один раз просит его перезагрузиться, и оно перечитывает файлы с диска. Сбой в чтении дополнений (время, лайк) не гасит сам трек.
* Два источника: показывается тот, где играет; если нигде не играет — медиа-сессия Windows, если она есть. Кнопки уходят туда, чей трек показан. Источник Windows от расширения не зависит.

### Аудиоустройства

* Показывать только избранные выходы и микрофоны из настроек, текущее устройство отмечено акцентом (полоска слева и значок, как в меню Windows 11). Имена сравниваются по вхождению без учёта регистра (Windows иногда меняет имена, например «2- Headset (Jabra)»). В строке — название так, как оно записано в настройках.
* Избранное не задано — вместо списка подсказка, куда его вписать (показывать все устройства нельзя: виртуальных, например VoiceMeeter, бывает два десятка).
* Смена устройства — для всех ролей (eConsole, eMultimedia, eCommunications). Текущим считается устройство роли eConsole.
* «Режим созвона» — кнопка «Созвон» в блоке звука: одно нажатие переключает и выход, и микрофон на `callMode`. Повторное нажатие возвращает прежние устройства — для каждой роли отдельно, как было. Состояние режима после перезапуска не сохраняется. Нет `callMode` в настройках — нет и кнопки.
* Подключение/отключение устройств отслеживать через `IMMNotificationClient` (NAudio 3: `MMDeviceNotificationClient`), отключённые избранные устройства показывать неактивными. Следить только пока панель развёрнута.
* Микшер (раздел «Программы» под устройствами): громкость и «без звука» для программ, которые звучат прямо сейчас (активные звуковые сессии текущего устройства вывода). Несколько сессий одной программы — одна строка. Программа появляется, когда начинает звучать, и исчезает, когда замолкает; никто не звучит — раздела нет. Только события сессий Core Audio, без опроса; подключается только пока панель развёрнута.

### Закреплённое

* Элементы из `pins`: телефон / тег / ссылка, у каждого своя иконка.
* Клик по телефону или тегу — копировать в буфер и коротко показать «Скопировано». Клик по ссылке — открыть в браузере; копирование ссылки — через кнопку при наведении.

## Логи

* Папка: `%LocalAppData%\EdgeDock\logs`.
* Писать только при проблемах: исключения, ошибки подключения к Outlook, ошибки настроек, и если процесс держит CPU > 2% дольше 60 с или его память > 150 МБ (проверка раз в минуту, не чаще). Память — собственный рабочий набор процесса, как «Память» в Диспетчере задач: полный рабочий набор включает ~100 МБ общих системных библиотек и даёт ложные тревоги. Когда всё в порядке — лог пустой.
* Ротация при запуске: удалять файлы старше 14 дней, общий размер папки — не более 2 МБ.
* Пункт «Открыть папку логов» в меню трея.

## Этапы

Работать строго по одному этапу. Каждый этап должен собираться и запускаться. После каждого этапа — коммит в git. Публикация на GitHub — после того, как модель виджета устоится.

1. Док. Окно, свободное перетаскивание по экрану, магнит к внешним краям, закрепление положения, разворот/сворачивание с задержками и анимацией, акриловый фон, тема, трей-меню, настройки из JSON, логи, скрытие при полноэкранных приложениях. Готово, если: виджет ставится в любое место и прилипает к краю при поднесении; после перезапуска оказывается там же; панель никогда не уходит за экран; полоска не разворачивается при случайном касании; не видна в Alt+Tab; не забирает фокус; в простое CPU ~0%.
2. Карман. Лента скриншотов и полка, перетаскивание внутрь и наружу. Готово, если: свежий скриншот появляется в ленте за секунду; снимок и файл с полки перетаскиваются в Telegram, Outlook и Проводник.
3. Звук. Музыка, аудиоустройства, режим созвона. Готово, если: переключение наушники ↔ колонки в один клик, режим созвона переключает и выход, и микрофон, и возвращает их обратно.
4. Встреча. Outlook 2013 через COM. Готово, если: повторяющиеся встречи отображаются; Outlook закрывается нормально при работающем виджете; полоска подсвечивается за 10 минут до встречи.
5. Закреплённое. Телефоны, теги, ссылки. Готово, если: клик копирует или открывает элемент, подтверждение «Скопировано» не мешает работе.

## Решения, принятые при обсуждении

* Модуль «Токены AI» убран целиком вместе с шифрованием ключей (DPAPI).
* Трей — собственный `Shell_NotifyIcon` и системное меню Win32 (без WinForms и сторонних пакетов). Иконка восстанавливается после перезапуска Проводника.
* Полноэкранный режим определяется по системным событиям (смена активного окна, уведомление о полноэкранном приложении), без опроса.
* Запускается только один экземпляр виджета.
* Per-Monitor DPI v2 в манифесте.
* Все элементы в окне не принимают клавиатурный фокус (`Focusable="False"`), иначе клик по ним активирует окно.
* Обводка панели — системная рамка DWM Windows 11.
* Программная отрисовка WPF (`RenderMode.SoftwareOnly`): интерфейс маленький и почти всегда неподвижен, а без Direct3D процесс занимает в разы меньше памяти. Прозрачность и акрил DWM не страдают.
* Акрил у окна без фокуса: рамка панели держится в «активном» состоянии через `WM_NCACTIVATE`, иначе DWM рисует сплошной цвет.
* Для автозапуска `publish.ps1` собирает exe в `%LocalAppData%\Programs\EdgeDock`, ярлык указывает туда.

## Правила работы для агента

* Не расширяй объём этапа по своей инициативе. Идеи записывай в `IDEAS.md`.
